# 入库指南（GitHub 连不上时）

`Recv failure: Connection was reset` 表示本机访问 GitHub 不稳定，与项目代码无关。

## 方式 A：自动镜像（已内置）

`config.yaml` 里配置了 `repo_mirrors`，会依次尝试 ghproxy / gitclone 等：

```powershell
.\.venv\Scripts\python.exe -m docpulse ingest --force-clone
```

若仍失败，可在 `config.yaml` 里换成你当前可用的镜像前缀。

## 方式 B：浏览器下载 ZIP（推荐）

1. 用浏览器打开（可配合代理）：
   - https://github.com/tiangolo/fastapi/archive/refs/heads/master.zip  
   - 或镜像站提供的 GitHub 加速下载同一 ZIP

2. 解压后得到文件夹 `fastapi-master`（名称可能略有不同）。

3. 放到项目目录，**最终路径**必须是：

   ```text
   data/repos/fastapi/docs/en/docs/...
   ```

   操作示例：

   - 若 `data/repos/fastapi` 已存在，先备份需要保留的内容
   - 将解压出的 `fastapi-master` **重命名**为 `fastapi`
   - 移动到 `data/repos/fastapi`

4. 入库（不访问 GitHub）：

   ```powershell
   # 在仓库根目录执行
   .\.venv\Scripts\python.exe -m docpulse ingest --no-sync
   ```

   成功时 `files` 通常为几十到上百，具体数量随 FastAPI 文档版本变化。

## 方式 C：手动 git clone

在仓库根目录执行（若 `data/repos/fastapi` 已存在，先确认其中没有需要保留的文件）：

```powershell
New-Item -ItemType Directory -Force data/repos | Out-Null
git clone --depth 1 --branch master https://github.com/tiangolo/fastapi.git data/repos/fastapi
```

然后：

```powershell
.\.venv\Scripts\python.exe -m docpulse ingest --no-sync
```

## 如何确认入库成功

查看统计表中的 `files` 数量。完整英文文档通常有几十到上百个 Markdown 文件。

或检查：

```text
data/state/fastapi/chunks.jsonl
```

行数应在数百～数千行量级。
